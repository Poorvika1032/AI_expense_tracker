# AI-Based Intelligent Travel Expense Prediction and Optimization System

A Flask and SQLite travel-planning project. It uses a saved scikit-learn Random Forest pipeline to estimate trip costs, compare travel modes, and evaluate predictions against expenses users record.

## Implemented features

- Registration and login with Werkzeug password hashing; active status and USER/ADMIN role checks.
- CSRF protection for state-changing forms and per-user ownership checks for trips, expenses, wishlist, favorites, and notifications.
- Random Forest expense prediction, Bus/Train/Car estimates, budget-aware transport choice, saved trip history, search/filter/pagination, trip duplication/edit/deletion.
- Model-based what-if scenarios and a budget optimizer. It considers transport modes and shorter durations; it does not reduce traveler count. Potential savings are stored, and optimizer runs can optionally link to a trip to track predicted-minus-actual variance as expenses are recorded.
- Per-trip actual expense CRUD; predicted-versus-actual MAE/RMSE and charts based only on trips with recorded actual spending.
- Responsive travel-tech dashboard and sign-in screens, live model-backed planner preview, interactive transport estimates, what-if sliders, dated trip calendar, and an in-app travel assistant that uses the saved prediction model and the signed-in user's history.
- Monthly reports, CSV, Excel, and generated PDF exports, date-filtered analytics, user profile/preferences, profile images, saved dark/light theme, reference currency conversion, savings totals, favorites, wishlist, dataset-backed recommendations, destination comparisons, rule-based itinerary, anomaly notifications, and authenticated JSON endpoints.
- Admin user activation/deactivation/deletion, activity logs, CSV dataset validation/upload, model retraining, model version history and activation.
- Additive database initialization retains the existing `users` and `travel_history` data.

## Setup and run

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
$env:SECRET_KEY = "replace-with-a-long-random-secret"
python app.py
```

Open `http://127.0.0.1:5000`. The saved model artifact is loaded automatically. To retrain on the bundled dataset, run `python train_model.py`. For HTTPS deployment set `COOKIE_SECURE=1`; configure a persistent secret in `SECRET_KEY` and keep Flask debug disabled.

## Admin access

Create or promote an account with `python -m flask --app app create-admin`. The password is entered without terminal echo. Registration never grants an admin role. Admin pages are linked from `/admin` and require the ADMIN role.

Admin dataset upload accepts CSV files up to 5 MB, validates the required feature and target columns, previews rows and reports missing/duplicate values. Admin training saves a new artifact under `models/`, records its metrics and activates the new version. Prior artifacts are retained and can be reactivated from the model versions page.

## Database and ML

SQLite is initialized at `database.db`. Main tables: `users`, `travel_history`, `expenses`, `wishlist`, `favorite_destinations`, `user_savings`, `notifications`, `datasets`, `model_versions`, and `activity_logs`.

The model pipeline uses OneHotEncoder with unknown-category support, StandardScaler for numeric inputs, and a multi-output RandomForestRegressor. Model inputs are source, destination, transportation, travelers, and days. Accommodation class, season, distance, and travel type are not model features because the bundled data does not contain those fields. No confidence interval is presented. The existing artifact was trained on 57 complete rows and reports holdout MAE about 254.44, MSE about 131,695.38, and R-squared about 0.767; these results are limited by the small dataset and single seeded split.

Dataset recommendations and destination comparisons use destinations actually present in the bundled CSV. The itinerary page is explicitly rule-based. PDF reports are generated by the app and CSV export includes predicted and entered actual spending.

## Remaining limitations

The ML dataset is small and does not support reliable confidence intervals or rich season/accommodation/distance modeling. Daily forecasts require sufficient dated expense history; otherwise the page reports that there is not enough data. Currency conversion uses daily reference rates and does not rewrite stored INR values. External travel data integrations remain future work. Daily estimates are statistical and are not per-category ML forecasts. Rule-based itinerary output does not claim to be generative AI.
